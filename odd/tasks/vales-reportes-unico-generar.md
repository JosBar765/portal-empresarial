# Vales: single "Reportes" tab (old one removed), "Generar" flow, error traceability

Branch: `feat/vales-reportes-2` (earlier uncommitted work lives in the same files, so no work-unit commits yet; the owner did not ask for commits).
Owner request (2026-11-20): (1) delete the old "Reportes" tab and let "Reportes 2" take its place under the name "Reportes"; (2) stop querying on every change: select report -> its extra filters -> time window -> "Generar" (renamed from "Actualizar"); bar focus becomes frontend-only over the generated data; (3) prepare exceptions well so the owner can tell where an error comes from.
Design: same UI as today (mockup waived: flow and wiring changes only).

## Decisions
- Tab label becomes "Reportes"; internal ids (`reportes2`, `#reportes2-vista`, `rep2-*`) stay to avoid churn. Tab opens with `vales.ver_reportes` (unchanged, no migration); each report keeps its own `vales.reporte_actividad_*`.
- Delete the old tab, its endpoints (`GET /reportes`, `/reportes/pdf`) and the dead code they used. Keep what Reportes 2 needs: period helpers and filter labels (move out of `valeReporteService.js`), `valeReporteGruposService.armar`, `valeReportePdfService`.
- Do NOT trim the rendimiento branches inside `valeReporteGruposService.armar`/`valeReportePdfService` in this feature (no tests; separate cleanup).
- Filter options come from a light endpoint `GET /api/vales/reportes/<reporte>/opciones` (no vale scan), so selectors show before generating.
- Counters per group (`todos` / `urgentes`) are computed by the server inside the report payload; the frontend only picks the group and filters the desglose. No second query for the focused bar. `soloUrgentes`/`asesorDesglose`/`tiendaDesglose` stay for the PDF only.
- After a reload: saved filters are restored, nothing is generated until "Generar". Changing a filter/window after generating keeps the old result and highlights "Generar" with a "filters changed" hint.
- Errors: every report request gets a short reference (`referencia`) and a code; the server logs one line with report, stage, user id, filters summary, status and the reference; the JSON carries `error`, `codigo`, `referencia`, `etapa`; the screen shows cause + reference; the client logs the same. 429 is logged and has its own message.
